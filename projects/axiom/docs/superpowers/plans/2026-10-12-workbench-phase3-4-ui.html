    Workbench Phases 3 and 4: Flow 3.0.1 UI Upgrade and Workbench UI Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Upgrade the UI to @apitomy/flow-ui 3.0.1 and build the Workflow Workbench page. The page has a three-pane layout: - a composition tree with revisions and publish; - tabbed editors for the workflow, action types and tools; - an AI chat.

    You and the AI take turns editing the same live drafts. AI workflow changes arrive as Flow change sets that the editor applies (live) or stages (review), and an AI turn can be undone.

    Architecture: - Data: a thin API layer (config/compositions.ts) over the Phase 2 REST routes, plus a typed SSE helper. - Pure logic in testable modules (pages/workbench/*.ts): - tree status - publish selection - turn and lock state - undo decision - preferences - Page: WorkbenchPage assembles a resizable three-pane layout from small components. - Workflow tab: the Flow WorkflowEditor, driven through its imperative handle. - Action type and tool tabs: controlled editors extracted from the existing detail pages, which are refactored to use them, so there is one editor implementation. - Chat: the existing AssistantChatPanel, with send and interrupt redirected to the composition routes.

    Tech Stack: React 19, TypeScript, PatternFly 6, react-router 7, @apitomy/flow-ui 3.0.1, Vitest with jsdom and Testing Library. The backend is Java/Quarkus, contract-first; this plan adds one endpoint.

    Spec: docs/superpowers/specs/2026-10-08-workflow-workbench-design.md, especially §2 (UI), §3 (REST) and §4 (errors). Flow reference: apitomy-flow/docs/user-guide/ai-assisted-editing.md.

    Global Constraints

    • UI commands, run in ui/: npx tsc -b --noEmit, npx vitest run <file>, npx vitest run.
    • Node modules: in a git worktree, run npm ci in the worktree's own ui/. Never symlink to, or modify, the main checkout's node_modules. Only Task 1 changes dependencies.
    • Backend: never run mvn clean, ./build.sh or any mvn install. Use mvn -q -pl app -am test -Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false. REST changes start in openapi.json.
    • Style: TypeScript and Java use 4-space indentation. Add JSDoc or Javadoc on exported or public functions and components. Use explicit types for exported APIs. Use git grep, not rg.
    • Commits: conventional commit messages, no AI attribution, no push.
    • localStorage keys: prefix with axiom.workbench.. Wrap every access in try/catch, as useTheme.ts does.
    • Flow handle use:
    • Pending change set, apply mode live: call handle.apply(cs).
    • Pending change set, apply mode review: call handle.propose(cs).
    • A stale rejection or onProposalResolved(id, 'stale') resolves as stale.
    • Accept or apply resolves as applied. Reject resolves as rejected.
    • Resolving change sets: every pending change set the UI receives must be resolved exactly once with POST /compositions/{id}/changeset-resolution {turnId, outcome, fromPending}.
    • fromPending is true when the set came from GET /compositions/{id} while the workbench was opening.
    • It is false when the set came from the live SSE composition-changeset event.
    • Saving the workflow:
    • Debounce workflow saves by 500 ms.
    • Flush any pending save before sending a chat message.
    • A save caused by an agent-origin change (meta.origin starts with agent:) carries turnId = the turn that produced the change set.
    • SSE event types:
    • composition-item-changed {compositionId, itemId, contentRevision, author, turnId}
    • composition-turn {compositionId, turnId, state}
    • composition-changeset {compositionId, turnId, changeSet}

    All three are top-level events. Consume them with sseClient.subscribe. - Mocking flow-ui in tests: component tests that render the editor mock @apitomy/flow-ui with vi.mock, as WorkflowRunDetailPage.test.tsx does. jsdom cannot render React Flow.
